# Chirpy

Chirpy is a lightweight Go backend for a micro-blogging service with user authentication, chirp posting, refresh token lifecycle management, and upgrade handling via webhook events.

## Features

- User registration with email and password
- Login with JSON Web Token (JWT) authentication
- Refresh token issuance and revocation
- Create, list, retrieve, and delete chirps
- Chirp length limit and profanity filtering
- Admin metrics page and reset endpoint for development
- External webhook support to upgrade users to Chirpy Red

## Architecture

- HTTP server in `main.go`
- SQL layer generated by `sqlc` under `internal/database`
- Authentication helpers in `internal/auth`
- Postgres persistence with user, chirp, and refresh token tables

## Requirements

- Go 1.26+
- PostgreSQL database
- `go` toolchain available

## Environment Variables

Create a `.env` file or set environment variables directly:

- `DB_URL` - PostgreSQL connection string
- `JWT_SECRET` - secret used to sign JWT tokens
- `POLKA_KEY` - secret key for verifying Polka webhook requests
- `PLATFORM` - set to `dev` to enable `/admin/reset`

## Database Setup

The project uses SQL migration files under `sql/schema`.

A minimal schema includes:

- `users`
- `chirps`
- `refresh_tokens`

Apply migrations using your preferred tool, or run the SQL files manually in Postgres.

## Running Locally

```bash
export DB_URL="postgres://user:password@localhost:5432/chirpy?sslmode=disable"
export JWT_SECRET="your_jwt_secret"
export POLKA_KEY="your_polka_key"
export PLATFORM="dev"
go run .
```

The server listens on port `8080` by default.

## API Endpoints

### Public

- `POST /api/users`
  - Register a new user
  - Request body: `{ "email": "...", "password": "..." }`

- `POST /api/login`
  - Authenticate a user
  - Request body: `{ "email": "...", "password": "..." }`
  - Response returns `token` and `refresh_token`

- `GET /api/chirps`
  - List chirps
  - Optional query params:
    - `author_id` - filter by user UUID
    - `sort=asc|desc` - sort by creation time

- `GET /api/chirps/{chirpID}`
  - Retrieve a chirp by ID

### Authenticated

Require `Authorization: Bearer <jwt>` header.

- `POST /api/chirps`
  - Create a chirp
  - Request body: `{ "body": "..." }`
  - Enforced 140-character limit and profanity masking

- `PUT /api/users`
  - Update authenticated user's email and password
  - Request body: `{ "email": "...", "password": "..." }`

- `DELETE /api/chirps/{chirpID}`
  - Delete a chirp owned by the authenticated user

- `POST /api/revoke`
  - Revoke a refresh token
  - Use the bearer token for the refresh token to revoke

### Token Management

- `POST /api/refresh`
  - Exchange a valid refresh token for a new JWT
  - Use the refresh token in `Authorization: Bearer <refresh_token>`

### Webhook

- `POST /api/polka/webhooks`
  - Receives external webhook events
  - Requires header-based API key matching `POLKA_KEY`
  - Upgrades users to `is_chirpy_red` when event is `user.upgraded`

### Admin

- `GET /admin/metrics`
  - Returns a simple metrics page showing file server hits

- `POST /admin/reset`
  - Clears all users in development mode only (`PLATFORM=dev`)

- `GET /api/healthz`
  - Health check endpoint

## Notes

- The service serves static assets from `/app/` mapped to the local working directory.
- Refresh tokens expire automatically after 60 days and can be revoked.
- User passwords are stored as hashed values using the included auth helpers.

## Development

- Build and run with `go run .`
- Add or regenerate SQL queries with `sqlc` if the schema changes
- Keep `JWT_SECRET` and `POLKA_KEY` secure in production
